## Objetivo

Realizar a implementação da UI e lógica contendo formulários para o painel administrativo, onde estão sendo utilizadas tabs para cada seção e navegação, atualmente a regra se concentra em `app/admin`

- **Visão Geral**: contém um 'apanhado' de informações mais gerais.
- **Barbearia**: contém dados da barbearia como nome, endereço, imagem e outras informações importantes.
- **Serviços**: contém dados do serviço pertencente aquela barberia.
- **Agendamentos**: contém dados sobre as reservas de horário da barberia.
  A idéia é realizar a implementação de CRUD para poder realizar diversas operações como(editar informações da barbearia selecionada, criar e editar serviços para barbearia e verificar os agendamentos por dia), assim como deletar informações pertinentes para o gerenciamento completo para um dono de barbearia.

## Regras Da Implementação
- Todos os formulários devem ser validados com RHF e Zod criando os esquemas conforme as entidades do Prisma na pasta `schemas` na raiz do projeto.
- DEVE _SEMPRE_ utilizar componentes do shadcn como `tabs, field, inputs e etc` para construção de formulários e componentes necessários.
- Reutilização de componentes criados em caso de reaproveitamento podem ser usados para facilitar a manutenção e reuso de forma inteligente
- PROIBIDO mexer em outros lugares do código, deve **SER** respeitada a arquitetura do projeto
- Preferível utilizar a estrutura desenhada abaixo criando componentes no lugar das `divs` para cada entidade
```tsx
        <TabsContent value="resume">
            <div>Visão geral</div>
        </TabsContent>
        <TabsContent value="babershop">
            <div>Barbearia</div>  {/* Aqui vem o componente <Componente/> invés dessa div genérica*/}
        </TabsContent>
        <TabsContent value="services">
            <div>Serviços</div>
        </TabsContent>
        <TabsContent value="bookings">
            <div>Agendamentos</div>
        </TabsContent>
```
- PROIBIDO USO de tipos `any`devem ser criados interfaces prontas como do Prisma ou criar própias
- PROIBIDO baixar outras libs e ferramentas que não estejam no projeto
- Utilzar o design system do `app/globals.css`, evitando uso de cores,fontes `harded-code` como `#FFFFFF` e sim preferir usar `bg-foreground` por exemplo
- PROIBIDO comentários longos e desnecessários sem nexo, seja claro e direto criando nomes de componentes e funções de forma para facilitar que o código fale por si só o que ele faz

## Critérios de aceite
[ ] - Sem any ou utilização de `TypeScript` obsoleto ou má práticas que julgar para o TS versão +5
[ ] - Não mexer no que foi solicitado e ajustar partes desncessárias
[ ] - Não **CRIAR** funcionalidades backend como novas `server-actions` ou chamadas ao Prisma e banco de dados, deve ser criado apenas o front-end
